# 0.2 alpha refresh — 2026-10-27

[Release workflow](https://github.com/vooyajs/vooya/actions/runs/40387724087) published this batch from
[`561e25e7`](https://github.com/vooyajs/vooya/commit/561e25e7a59c945d51d8328af262b39b7946686e). Packages remain independently
versioned; this is an alpha refresh, not a stable or beta promotion. The first
attempt passed the full prepublication gate and uploaded all eleven candidates,
then failed because registry metadata had not propagated within its retry window.
That failed attempt remains part of the release history. The second attempt failed
at the Webpack watch startup stability assertion (`3 !== 1`). A subsequent full
`npm run test:rust-bundlers` run passed, including both bundlers, both frameworks
and watch recovery. The suspected timing-sensitive acceptance issue remains under
investigation in [#219](https://github.com/vooyajs/vooya/issues/219); neither workflow
attempt is recorded as successful.

## Changes and migration

- Author ordinary Rust `.rs` Components and Stores. The custom-format parser,
  formatter, loaders and related APIs are removed from this alpha line.
- The dedicated precompiled Vue component-package builder and validator are
  removed. Authors own JS/WASM wrappers, assets, declarations and npm metadata.
- Rust names containing acronyms, such as `HTTPView` and `HTTPClient`, now
  resolve the matching macro-generated WASM exports.
- Generated Rust bindings can retry failed loading; Store attachment errors,
  late cleanup and disposal from a change listener follow the corrected lifecycle.
- Store snapshot diagnostics preserve the last successful build and report
  authored source positions where available. Missing metadata remains explicitly
  unknown; exact Rust module/type identity is still tracked separately.
- CSS selector and TOML parser dependencies require patched releases, as
  recorded in [PR #216](https://github.com/vooyajs/vooya/pull/216).

See the [migration guide](../../project/retired-authoring.md) before updating an
application using removed source formats or helpers. Historical npm versions
retain their behavior. Go/Zig providers, a public provider protocol, isolated
per-root artifacts and a stable release remain outside this batch.

## Verification and evidence

The first Release attempt passed `verify:release`, including the full CI and
browser/bundler suites and clean locally packed Vue/React consumers, on the exact
release commit. After registry propagation, independent acceptance checked exact
registry versions, internal pins and protected tags against the original baseline,
then installed Vue and React consumers from npm for strict TypeScript checks,
production builds and Chromium interaction on macOS with Node 22.22.2.
Recovery retained the same release SHA and original protected-tag baseline.
After independent acceptance, the repository's `create-github-releases` helper
created all eleven missing prereleases from that exact commit. Existing npm
versions were not republished. All eleven npm tarball integrity hashes match the
original first-attempt publication artifacts.

The workflow artifacts retain the original protected-tag baseline, publish plan and
publication evidence under the release SHA. The [Vite GitHub prerelease](https://github.com/vooyajs/vooya/releases/tag/%40vooya/vite%400.2.0-alpha.1)
also retains the independent acceptance receipt, original baseline and tarball
integrity comparison as downloadable assets. Independent acceptance covers all
twelve public packages; that does not mean preset was republished.
Solid/Svelte retain their documented experimental fixture coverage and do not
inherit the separate Vue/React registry-browser acceptance claim. Octane remains
private. Package publication and documentation-site deployment are separate.

The [first alpha.0 recovery record](./0.2.0-alpha.0.md) remains unchanged; it
records an earlier workflow failure and must not be rewritten as a successful run.
