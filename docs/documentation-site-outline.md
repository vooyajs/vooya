# Documentation Site Outline

An initial Vooya documentation site can stay small while still giving new contributors a reliable path through the project. The landing page should explain the runtime model, the installation page should show the supported package-manager flow, and the guides should separate component authoring, scoped styling, events, and Vite integration.

Each guide should state the supported version or experimental status of the feature it describes. Examples should be minimal, runnable, and free of private project paths. A compatibility page should link behavior to the relevant issue or test so that documentation does not silently outlive the implementation.

The site should also include contribution, troubleshooting, and security guidance. Clear boundaries are more valuable than a large number of pages during the beta period.
